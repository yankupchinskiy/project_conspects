## 30. Алгоритмы топологической сортировки (алгоритмы Кана и Тарьяна)

Топологическая сортировка — фундаментальная алгоритмическая задача на ориентированных ациклических графах (DAG), лежащая в основе планирования задач, разрешения зависимостей, компиляции и многих других приложений. В этом разделе мы подробно рассмотрим постановку задачи и два классических алгоритма: алгоритм Кана (Kahn, 1962), основанный на удалении вершин с нулевой входящей степенью, и алгоритм Тарьяна (Tarjan), использующий поиск в глубину.

---

### 30.1. Постановка задачи

**Определение 30.1 (Топологическая сортировка).**  
Пусть $G = (V, E)$ — ориентированный ациклический граф (DAG). **Топологической сортировкой** (topological order) называется линейное упорядочение вершин $v_1, v_2, \dots, v_{|V|}$, такое что для любого ориентированного ребра $(u, v) \in E$ вершина $u$ предшествует вершине $v$ в этом порядке: $u$ встречается раньше $v$.

**Свойства:**
- Топологическая сортировка существует **тогда и только тогда**, когда граф является DAG. Если в графе есть цикл, топологическая сортировка невозможна.
- В общем случае DAG может иметь несколько допустимых топологических сортировок.
- Задача находит применение в планировании выполнения задач с зависимостями, компиляции исходного кода, разрешении зависимостей пакетов, вычислении выражений и т.д.

---

### 30.2. Алгоритм Кана (Kahn's algorithm)

Алгоритм Кана — итеративный метод, основанный на понятии **входящей степени** (indegree) вершин. Идея: многократно выбирать вершины, у которых нет входящих рёбер (т.е. нет невыполненных зависимостей), добавлять их в результат и удалять из графа вместе с исходящими рёбрами.

#### 30.2.1. Описание алгоритма

1. Вычислить входящие степени $indeg[v]$ для всех вершин $v \in V$.
2. Поместить все вершины с $indeg[v] = 0$ в очередь $Q$ (можно использовать любую структуру FIFO, например, очередь или стек; порядок повлияет на конкретную допустимую сортировку).
3. Пока очередь не пуста:
   - Извлечь вершину $u$ из $Q$.
   - Добавить $u$ в конец результирующего списка $L$.
   - Для каждого исходящего ребра $(u, v)$:
     - Уменьшить $indeg[v]$ на 1.
     - Если $indeg[v]$ стал равен 0, добавить $v$ в $Q$.
4. Если количество вершин в $L$ меньше $|V|$, то граф содержит цикл и топологическая сортировка невозможна. Иначе $L$ — топологическая сортировка.

#### 30.2.2. Псевдокод

```
function KahnTopologicalSort(G):
    n = |V|
    indeg = массив размера n, заполненный 0
    для каждого ребра (u, v) в E:
        indeg[v] += 1

    Q = пустая очередь
    для v от 1 до n:
        если indeg[v] == 0:
            Q.enqueue(v)

    L = пустой список

    пока Q не пуста:
        u = Q.dequeue()
        L.добавить(u)
        для каждого соседа v вершины u (по исходящим дугам):
            indeg[v] -= 1
            если indeg[v] == 0:
                Q.enqueue(v)

    если len(L) != n:
        ошибка "Граф содержит цикл, топологическая сортировка невозможна"

    вернуть L
```

#### 30.2.3. Анализ сложности

- Инициализация `indeg`: $O(|V| + |E|)$ — проход по всем рёбрам.
- Работа с очередью: каждая вершина помещается в очередь и извлекается ровно один раз. Каждое ребро обрабатывается один раз при уменьшении степени. Следовательно, общая сложность $O(|V| + |E|)$.
- Дополнительная память: $O(|V|)$ для массива `indeg` и очереди.

Алгоритм Кана работает за линейное время и легко реализуется. Порядок обработки зависит от структуры очереди: FIFO даёт одну из возможных сортировок; использование стека или очереди с приоритетами (например, по номеру вершины) позволяет получать лексикографически наименьшую топологическую сортировку.

### 30.3. Алгоритм Тарьяна (DFS-based topological sort)

Алгоритм Тарьяна для топологической сортировки основан на обходе в глубину и временах завершения обработки вершин. Он также линейен и попутно может обнаружить наличие цикла.

#### 30.3.1. Идея

При обходе DFS ориентированного графа вершина, у которой время завершения (finish time) больше, должна в топологическом порядке стоять раньше? Вспомним свойство: если ребро $u \to v$ существует, то в DAG время завершения $u$ **больше**, чем время завершения $v$. Поэтому если отсортировать вершины по убыванию времени завершения DFS, получим топологический порядок.

**Альтернативное объяснение:** выполним рекурсивный DFS, и при выходе из вершины будем добавлять её в начало списка (или в стек). Обратный порядок этого списка даст топологическую сортировку.

**Обнаружение цикла:** если во время обхода встречается обратное ребро (ребро, ведущее к вершине, находящейся в текущем рекурсивном стеке), то граф содержит цикл. Это стандартный метод проверки ацикличности ориентированного графа.

#### 30.3.2. Псевдокод (с явным обнаружением цикла)

```
function TarjanTopologicalSort(G):
    n = |V|
    color = массив размера n, заполненный WHITE  // 0 = WHITE, 1 = GRAY, 2 = BLACK
    L = пустой список (или стек)
    
    function dfs(u):
        color[u] = GRAY
        для каждого соседа v вершины u:
            если color[v] == GRAY:
                ошибка "Граф содержит цикл, топологическая сортировка невозможна"
            иначе если color[v] == WHITE:
                dfs(v)
        color[u] = BLACK
        L.добавить_в_начало(u)   // или L.push(u) и потом развернуть

    для v от 1 до n:
        если color[v] == WHITE:
            dfs(v)

    вернуть L
```

*Пояснение:*
- `WHITE` — вершина ещё не посещена.
- `GRAY` — вершина в процессе обработки (находится в стеке рекурсии).
- `BLACK` — вершина полностью обработана.
- Если встречаем ребро, ведущее в серую вершину, это обратное ребро, означающее цикл.
- Добавление вершины в начало списка при выходе из `dfs` эквивалентно сортировке по убыванию времени завершения.

#### 30.3.3. Анализ сложности

- Время: $O(|V| + |E|)$, так как каждая вершина и каждое ребро посещаются один раз.
- Память: $O(|V|)$ для массива цветов и стека рекурсии (в худшем случае глубина рекурсии $O(|V|)$). Можно реализовать итеративно с явным стеком для экономии памяти.

#### 30.3.4. Примечание

В литературе под «алгоритмом Тарьяна» чаще понимают алгоритм поиска компонент сильной связности (Тарьян, 1972), который также использует DFS и lowlink. Однако тот же автор описал и метод топологической сортировки с помощью DFS; поэтому во многих источниках DFS-алгоритм топологической сортировки связывают с именем Тарьяна, хотя по сути это классическое применение поиска в глубину.

### 30.4. Пример работы обоих алгоритмов

Рассмотрим DAG с вершинами A, B, C, D, E и рёбрами:
- A → B
- A → C
- B → D
- C → D
- D → E
- C → E

Этот граф моделирует зависимости: A должен быть выполнен раньше B и C, и т.д.

**Алгоритм Кана:**
- Входящие степени: A:0, B:1, C:1, D:2, E:2.
- Очередь: [A].
- Извлекаем A → L = [A]; уменьшаем степени B (0) и C (0) → добавляем B, C в очередь. Очередь [B, C] (порядок зависит от порядка добавления, пусть B, затем C).
- Извлекаем B → L = [A, B]; уменьшаем D (1). Очередь [C].
- Извлекаем C → L = [A, B, C]; уменьшаем D (0) и E (1). D добавляется в очередь. Очередь [D].
- Извлекаем D → L = [A, B, C, D]; уменьшаем E (0). E добавляется. Очередь [E].
- Извлекаем E → L = [A, B, C, D, E].
- Итого порядок: A, B, C, D, E. Допустимая топологическая сортировка.

**Алгоритм Тарьяна (DFS):**
- Запускаем DFS из A (WHITE). Переходим A → B → D → E. Из E нет исходящих, добавляем E в начало списка (L = [E]), возврат. D: все соседи обработаны, добавляем D → L = [D, E]. Возврат к B: добавляем B → L = [B, D, E]. Возврат к A, продолжаем в C: C → D (уже BLACK), C → E (BLACK). Завершаем C → L = [C, B, D, E]. Завершаем A → L = [A, C, B, D, E].
- Обратный порядок (или читаем список как есть — зависит от того, добавляли в начало или в конец). Мы добавляли в начало, итоговый список L = [A, C, B, D, E]. Это тоже допустимая топологическая сортировка (A→C, A→B, C→D и B→D, D→E). Проверяем: A раньше C и B, C раньше D, B раньше D, D раньше E — верно.

Оба алгоритма дают правильные результаты.

### 30.5. Сравнение алгоритмов

| Характеристика               | Алгоритм Кана                           | Алгоритм Тарьяна (DFS)                  |
|------------------------------|-----------------------------------------|------------------------------------------|
| **Метод**                    | Итеративный, на основе indegree        | Рекурсивный/итеративный, обход в глубину |
| **Структура данных**         | Очередь (или стек)                     | Стек рекурсии (или явный стек)           |
| **Обнаружение цикла**        | Если обработано менее \|V\| вершин      | При обнаружении обратного ребра          |
| **Зависимость от порядка**   | Порядок зависит от структуры очереди; можно получить лексикографически наименьший (с приоритетной очередью) | Порядок зависит от порядка обхода; обычно даёт «глубинный» порядок |
| **Потоковая обработка**      | Легко обрабатывать граф по мере удаления вершин (потоковая топологическая сортировка) | Требует полного графа для начала DFS |
| **Параллелизм**              | Легко параллелится (одновременно можно обрабатывать несколько вершин с indeg=0) | Сложнее для параллелизации |

Оба алгоритма имеют линейную сложность $O(|V|+|E|)$ и являются эталонными решениями.

### 30.6. Применения топологической сортировки

- **Планирование задач (Task scheduling):** Есть набор задач, некоторые из которых должны быть выполнены раньше других (например, проектное управление, критический путь). Топологическая сортировка даёт допустимый порядок выполнения.
- **Системы сборки и разрешения зависимостей:** Make, Maven, Gradle, пакетные менеджеры (npm, pip) определяют порядок сборки/установки модулей.
- **Компиляция:** Порядок компиляции модулей, вычисление выражений в электронных таблицах (формулы, зависящие от других ячеек).
- **Обработка графов зависимостей в программировании:** Инструкции в языках описания аппаратуры (HDL), раскрутка циклов в оптимизации компиляторов.
- **Критический путь в PERT-диаграммах:** Для управления проектами.
- **Построение расписаний курсов (curriculum scheduling):** Курсы, которые требуют пререквизитов.

---

### 30.7. Заключение

Топологическая сортировка — базовая операция на ориентированных ациклических графах. Алгоритм Кана, интуитивно удаляющий вершины без предшественников, и алгоритм Тарьяна на основе DFS — оба линейны по времени, просты в реализации и взаимодополняющи. Понимание этих алгоритмов необходимо для решения широкого круга задач, связанных с упорядочиванием и анализом зависимостей.
