## 29. Построение наибольшего паросочетания алгоритмом Форда — Фалкерсона

Задача о **наибольшем паросочетании** в двудольном графе — классическая комбинаторная проблема, которая элегантно сводится к **задаче о максимальном потоке** в транспортной сети. Алгоритм Форда — Фалкерсона (особенно в реализации Эдмондса — Карпа) позволяет решить её эффективно, используя технику увеличивающих путей. В этом разделе подробно разобрано сведение, работа алгоритма, его корректность и сложность.

---

### 29.1. Сведение паросочетания в двудольном графе к максимальному потоку

Пусть дан двудольный граф $G = (U \cup V, E)$, где $U$ и $V$ — доли. Требуется найти **наибольшее паросочетание**, т.е. множество рёбер $M \subseteq E$, в котором никакие два ребра не имеют общей вершины, и размер $|M|$ максимален.

**Построение сети $N = (V_N, E_N)$:**
- Добавим **источник** $s$ и **сток** $t$.
- Ориентируем все рёбра из $U$ в $V$.
- Проведём дуги из $s$ в каждую вершину $u \in U$ с пропускной способностью $c(s,u) = 1$.
- Проведём дуги из каждой вершины $v \in V$ в $t$ с пропускной способностью $c(v,t) = 1$.
- Для каждого исходного ребра $(u,v) \in E$ (где $u \in U, v \in V$) установим пропускную способность $c(u,v) = 1$ (или можно сделать $c(u,v) = \infty$, но 1 удобнее для целочисленности).

Таким образом, все пропускные способности — единицы. Источник и сток являются общими для всех вершин долей.

**Связь между потоком и паросочетанием:**
- Любой целочисленный поток в этой сети соответствует паросочетанию: если по ребру $(u,v)$ идёт единичный поток, то ребро $\{u,v\}$ включается в паросочетание.
- Ограничения пропускной способности из $s$ и в $t$ гарантируют, что каждая вершина $u \in U$ и каждая $v \in V$ инцидентна не более чем одному ребру с потоком 1 — это в точности условие паросочетания.
- Величина потока $|f|$ равна размеру паросочетания.

Таким образом, задача о наибольшем паросочетании сводится к поиску **максимального целочисленного потока** из $s$ в $t$ в построенной сети.

Поскольку все пропускные способности целые, а алгоритм Форда — Фалкерсона при целых пропускных способностях всегда находит целочисленный максимальный поток, он естественным образом даёт наибольшее паросочетание.

### 29.2. Алгоритм Форда — Фалкерсона для паросочетания

Применим стандартный метод увеличивающих путей к нашей сети с единичными пропускными способностями.

**Инициализация:**
- Задаём начальный поток $f(e) = 0$ для всех рёбер.
- Строим остаточную сеть $G_f$ с пропускными способностями $c_f(u,v) = c(u,v) - f(u,v)$ и обратными рёбрами $c_f(v,u) = f(u,v)$.

**Основной цикл:**
Пока в остаточной сети существует путь из $s$ в $t$:
1. Найти **увеличивающий путь** $P$ (например, с помощью BFS или DFS).
2. Определить минимальную остаточную пропускную способность вдоль пути: $\Delta = \min_{e \in P} c_f(e)$. Так как все пропускные способности равны 1, $\Delta = 1$.
3. **Увеличить поток** вдоль $P$ на $\Delta = 1$: для каждого прямого ребра $e \in P$ увеличить $f(e)$ на 1, а для обратных — уменьшить на 1 (или эквивалентно обновить остаточные пропускные способности).
4. Величина потока возрастает на 1.

**Интерпретация в терминах паросочетания:**
- Первоначально $M = \emptyset$.
- Каждый увеличивающий путь $P$ в остаточной сети соответствует **увеличивающему пути** для текущего паросочетания $M$. Путь начинается в $s$, затем идёт в непокрытую вершину $u \in U$ (по прямому ребру), затем чередует рёбра не из $M$ (прямые) и рёбра из $M$ (проходимые в обратном направлении), и заканчивается в непокрытой вершине $v \in V$ и стоке $t$.
- Увеличение потока на 1 меняет статус рёбер вдоль пути: рёбра, не входившие в $M$, добавляются; рёбра, входившие в $M$, удаляются. Размер паросочетания увеличивается на 1.
- Когда увеличивающих путей не остаётся, поток максимален, а паросочетание — наибольшее.

Таким образом, алгоритм Форда — Фалкерсона в точности реализует метод увеличивающих путей для паросочетаний, известный как **алгоритм Куна** (в двудольном случае). Разница лишь в форме реализации: Куна обычно описывают через DFS по чередующимся путям, а Форда — Фалкерсона — через остаточную сеть, но суть одна.

### 29.3. Псевдокод (версия с остаточной матрицей)

```
function MaxMatchingFordFulkerson(U, V, E):
    // построение сети
    n = |U| + |V| + 2
    s = 0
    t = n - 1
    // индексация: U: 1..|U|, V: |U|+1 .. |U|+|V|
    c = матрица n×n, заполненная 0
    для u в U:
        c[s][u] = 1
    для v в V:
        c[v + |U|][t] = 1
    для (u,v) в E:
        c[u][v + |U|] = 1

    cf = копия c   // остаточные пропускные способности
    max_flow = 0

    пока истина:
        // поиск увеличивающего пути через DFS (можно BFS)
        visited = массив размера n, заполненный false
        delta = dfs(s, t, INF, visited, cf)
        если delta == 0:
            break
        max_flow += delta

    // восстановление паросочетания по потоку
    matching = []
    для u в U:
        для v в V:
            если cf[v + |U|][u] == 1:   // был поток u->v? если c_original=1 и cf[u][v]=0, то поток 1
                matching.добавить((u, v))
    вернуть matching

function dfs(u, t, flow, visited, cf):
    если u == t:
        вернуть flow
    visited[u] = true
    для v от 0 до n-1:
        если not visited[v] и cf[u][v] > 0:
            pushed = dfs(v, t, min(flow, cf[u][v]), visited, cf)
            если pushed > 0:
                cf[u][v] -= pushed
                cf[v][u] += pushed
                вернуть pushed
    вернуть 0
```

Для реальной реализации удобнее использовать списки смежности и хранить поток явно, но данная схема иллюстрирует идею.

### 29.4. Пример работы

Рассмотрим двудольный граф: $U = \{1,2,3\}$, $V = \{A,B,C\}$. Рёбра: 1-A, 1-B, 2-B, 2-C, 3-A.

**Сеть:** источник s, сток t. Дуги s→1, s→2, s→3; A→t, B→t, C→t; все способности 1.

**Шаг 1.** Начальный поток нулевой. Остаточная сеть совпадает с исходной. Находим увеличивающий путь, например, s → 1 → A → t. Увеличиваем поток на 1. Паросочетание: {1-A}.

**Шаг 2.** Остаточная сеть: s→1 (0), обратное 1→s (1); 1→A (0), A→1 (1); A→t (0), t→A (1). Остальные прямые дуги s→2, s→3, B→t, C→t, 2→B, 2→C, 3→A (но 3→A имеет способность 1, но A уже соединена с t с нулевой способностью? В остаточной сети A→t отсутствует, но есть обратное t→A, значит, A не может напрямую достичь t. Однако путь может пройти через обратные рёбра.) Ищем путь: s → 2 → B → t. Увеличиваем. Паросочетание: {1-A, 2-B}.

**Шаг 3.** Аналогично ищем путь. s → 3 → A → 1 → ? Обратное ребро A→1 существует. Путь: s → 3 → A → 1 → B? 1→B прямое существует (способность 1), B→t ещё есть. Путь s → 3 → A → 1 → B → t? Проверим: s→3 (1), 3→A (1), A→1 (обратное, способность 1, так как поток 1→A был 1), 1→B (1), B→t (1). Это увеличивающий путь длины 5. Увеличиваем поток на 1. Теперь паросочетание меняется: ребро 1-A удаляется, добавляются 3-A и 1-B. Итого {2-B, 3-A, 1-B}? Но 1-B и 2-B — обе вершины B? Это конфликт. Значит, я ошибся: после увеличения пути поток изменится: по пути s→3→A→1→B→t добавится поток 1. Это означает: включаем 3-A, 1-B, выключаем 1-A. Получим: 3-A, 1-B, 2-B? Но B будет инцидентна двум рёбрам, что невозможно, так как пропускная способность B→t = 1. Давайте аккуратнее. Перед шагом 3 поток: 1→A, 2→B. Остаточные способности: s→1 (0), 1→s (1); s→2 (0), 2→s (1); s→3 (1). A→t (0), t→A (1); B→t (0), t→B (1); C→t (1). Рёбра U-V: 1→A (0), A→1 (1); 1→B (1); 2→B (0), B→2 (1); 2→C (1); 3→A (1). Теперь ищем путь из s в t. Остаточный граф:
s→3 (1)
3→A (1)
A→1 (1)
1→B (1)
B→t? B→t = 0, но есть t→B (1) — не в ту сторону. Значит, B→t нет, путь через B в t невозможен. А как же путь s→3→A→1→B→t? Он не существует, потому что B→t = 0. Значит, такого пути нет. Попробуем другой: s→3→A→1→B→2→C→t. Проверяем: s→3 (1), 3→A (1), A→1 (1), 1→B (1), B→2 (обратное, 1), 2→C (1), C→t (1). Это путь! Он использует обратное ребро B→2 (так как есть поток 2→B). Длина 7. Увеличиваем на 1. Что произойдёт? Прямые дуги s→3, 3→A, 1→B, 2→C, C→t — поток увеличится; обратные A→1, B→2 — поток уменьшится. Исходный поток 1→A и 2→B. После увеличения: поток 1→A станет 0 (уменьшили), 2→B станет 0 (уменьшили), добавятся 3→A, 1→B, 2→C. Итоговое паросочетание: {3-A, 1-B, 2-C}. Размер 3, максимальный. Это соответствует действительности: в исходном графе максимальное паросочетание включает 3 ребра, например, 1-B, 2-C, 3-A.

Таким образом, алгоритм нашел увеличивающий путь и увеличил размер паросочетания.

### 29.5. Сложность

При использовании **DFS** для поиска пути (базовый Форд — Фалкерсон) сложность составляет $O(|E| \cdot f_{\max})$, где $f_{\max} \le \min(|U|,|V|) \le |V|/2$. Поиск DFS занимает $O(|E|)$. Итого $O(|V| \cdot |E|)$ в худшем случае. Это псевдополиномиальная оценка, но для паросочетаний она полиномиальна, так как максимальный поток ограничен размером долей.

При использовании **BFS** (алгоритм Эдмондса — Карпа) число увеличений будет также не более $|V|/2$, а каждый BFS требует $O(|E|)$. Сложность остаётся $O(|V| \cdot |E|)$. Хотя в общем случае Эдмондс — Карп даёт $O(|V| \cdot |E|^2)$, но в сетях с единичными пропускными способностями каждое увеличение обрабатывает путь, и общее число фаз (BFS) ограничено $O(|V|)$, но всё равно $O(|V| \cdot |E|)$.

Однако существует более эффективный **алгоритм Хопкрофта — Карпа**, который также основан на увеличивающих путях, но использует поиск максимального множества кратчайших путей в одной фазе, что даёт сложность $O(\sqrt{|V|} \cdot |E|)$. Он также может быть выведен из алгоритма Диница для единичных сетей.

Тем не менее, алгоритм Форда — Фалкерсона остаётся простым для понимания и реализации, и для небольших графов вполне применим.

---

### 29.6. Сравнение с прямым алгоритмом Куна

Алгоритм Куна (тоже основанный на увеличивающих путях) обычно реализуется рекурсивным DFS по чередующимся рёбрам и имеет ту же асимптотику $O(|V| \cdot |E|)$. Разница в реализации:
- В подходе Форда — Фалкерсона строится явная остаточная сеть и поток.
- Алгоритм Куна работает непосредственно с двудольным графом, поддерживая массив паросочетания.

По сути это одно и то же; выбор зависит от контекста. Алгоритм Куна проще для ручного кодирования, а сведение к потоку позволяет использовать готовые библиотеки для максимального потока и легко обобщается на взвешенные задачи (например, задача о назначениях может решаться min-cost flow).

---

### 29.7. Общий случай (произвольные графы)

Наибольшее паросочетание в **произвольном** (не двудольном) графе не может быть найдено простым сведением к потоку, потому что не существует естественного разбиения на две доли. Попытка ориентировать рёбра и добавить источник и сток нарушит симметрию и не гарантирует корректности. Для произвольных графов требуется более сложный **алгоритм Эдмондса** (сжатия цветков), который также является обобщением метода увеличивающих путей, но работает с контракцией нечётных циклов. Этот алгоритм может быть реализован через поток в некотором обобщённом смысле, но не напрямую алгоритмом Форда — Фалкерсона.

---

### 29.8. Заключение

Алгоритм Форда — Фалкерсона предоставляет универсальный метод для построения наибольшего паросочетания в двудольном графе. Сведение к задаче о максимальном потоке с единичными пропускными способностями сохраняет структуру паросочетания и позволяет применить эффективные техники поиска увеличивающих путей. Получающийся алгоритм концептуально прост, легко реализуется и служит отличной иллюстрацией взаимосвязи потоковых и комбинаторных задач. Для практического использования на больших двудольных графах часто применяют оптимизированные версии (Хопкрофт — Карп), но лежащий в их основе принцип остаётся тем же.
