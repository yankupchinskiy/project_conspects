# Проблемы шаблонных конструкторов и универсальные ссылки

## Проблемы шаблонных конструкторов

### 1. **Неявное подавление специальных функций-членов**

```cpp
class MyClass {
public:
    // ❌ ПРОБЛЕМА: Этот шаблонный конструктор может блокировать
    // генерацию конструкторов копирования/перемещения
    template<typename T>
    MyClass(T&& value) : data(std::forward<T>(value)) {}
    
private:
    int data;
};

MyClass a(10);
MyClass b = a;  // ❌ Ошибка компиляции! Нет конструктора копирования
                // Шаблонный конструктор не считается конструктором копирования
```

### 2. **Неограниченные шаблонные конструкторы**

```cpp
class Widget {
public:
    // Этот конструктор слишком общий!
    template<typename T>
    Widget(const T& other) : value(other.value) {}
    
private:
    int value;
};

// Нежелательные инстанциации:
Widget w1(42);      // OK
Widget w2("text");  // Ошибка компиляции, но сложная
Widget w3(w1);      // Хотим конструктор копирования, а получаем шаблонный
```

### 3. **Конфликт с конструктором копирования**

```cpp
class Example {
public:
    // Конструктор копирования
    Example(const Example& other) { /* ... */ }
    
    // Шаблонный конструктор
    template<typename T>
    Example(T&& other) { /* ... */ }
};

Example e1;
Example e2 = e1;  
// ❌ Неоднозначность: может вызваться как конструктор копирования,
// так и шаблонный конструктор (инстанцированный как Example(Example&))
```

### 4. **Проблема с наследованием**

```cpp
template<typename T>
class Base {
public:
    template<typename U>
    Base(U&& value) { /* ... */ }
};

class Derived : public Base<int> {
public:
    // Конструкторы Derived не могут автоматически делегировать
    // шаблонному конструктору Base
    Derived(int x) : Base<int>(x) {}  // Явно нужно указывать
    
    // А вот это не сработает:
    // template<typename U>
    // Derived(U&& value) : Base(value) {}  // ❌ Какой тип Base?
};
```

## Решения проблем шаблонных конструкторов

### 1. **Ограничение с помощью SFINAE**

```cpp
#include <type_traits>

class SafeWidget {
public:
    // Основной конструктор копирования
    SafeWidget(const SafeWidget&) = default;
    
    // Шаблонный конструктор с ограничением
    template<typename T,
             typename = std::enable_if_t<
                 !std::is_same_v<SafeWidget, std::decay_t<T>> &&
                 !std::is_base_of_v<SafeWidget, std::decay_t<T>>
             >>
    SafeWidget(T&& value) : data(std::forward<T>(value)) {}
    
private:
    int data;
};
```

### 2. **Использование концептов (C++20)**

```cpp
template<typename T>
concept NotWidget = !std::same_as<std::remove_cvref_t<T>, Widget>;

class Widget {
public:
    Widget(const Widget&) = default;
    
    template<NotWidget T>
    Widget(T&& value) : data(std::forward<T>(value)) {}
    
private:
    int data;
};
```

### 3. **Явные специализации для копирования/перемещения**

```cpp
class ExplicitExample {
public:
    // Явно определяем все специальные функции
    ExplicitExample() = default;
    ExplicitExample(const ExplicitExample&) = default;
    ExplicitExample(ExplicitExample&&) = default;
    
    // Шаблонный конструктор только для других типов
    template<typename T>
    ExplicitExample(T&& value) 
        : data(convert(std::forward<T>(value))) {}
    
private:
    static int convert(auto&& val) { return val; }
};
```

# Универсальные ссылки (Universal References)

## Что это такое?

Универсальная ссылка — это термин, введённый Скоттом Мейерсом для описания ссылок, которые могут связываться как с lvalue, так и с rvalue в зависимости от контекста.

### **Основные признаки**:

```cpp
// Универсальная ссылка - T&& с выводом типа
template<typename T>
void func(T&& arg);  // T&& - универсальная ссылка

// auto&& - также универсальная ссылка
auto&& var = expression;

// Но: определенный тип && - это rvalue-ссылка
template<typename T>
class Widget {
    void process(Widget&& obj);  // Rvalue-ссылка, НЕ универсальная!
    
    template<typename U>
    void work(U&& param);        // Универсальная ссылка!
};
```

## Механизм работы

### 1. **Вывод типа и свёртка ссылок (reference collapsing)**

```cpp
template<typename T>
void example(T&& param) {
    // Правила свёртки ссылок:
    // T& + & → T&
    // T& + && → T&
    // T&& + & → T&
    // T&& + && → T&&
}

int x = 10;
example(x);   // T = int&,  T&& = int& && → int&  (lvalue)
example(42);  // T = int,   T&& = int&&    → int&& (rvalue)
```

### 2. **Идеальная передача (perfect forwarding)**

```cpp
#include <utility>

// Универсальная ссылка + std::forward = идеальная передача
template<typename T>
void wrapper(T&& arg) {
    // Сохраняем категорию значения (lvalue/rvalue)
    process(std::forward<T>(arg));
}

void process(int&);   // Для lvalue
void process(int&&);  // Для rvalue

int a = 5;
wrapper(a);        // Вызовет process(int&)
wrapper(10);       // Вызовет process(int&&)
wrapper(std::move(a)); // Вызовет process(int&&)
```

## Различия: универсальные ссылки vs rvalue-ссылки

```cpp
// СИТУАЦИЯ 1: Шаблон функции
template<typename T>
void f1(T&& param);  // УНИВЕРСАЛЬНАЯ ссылка

void f2(int&& param); // RVALUE-ссылка (фиксированный тип)

int x = 10;
f1(x);  // OK: T = int&, param = int&
f1(20); // OK: T = int, param = int&&

// f2(x);  // ❌ Ошибка: нельзя привязать lvalue к rvalue-ссылке
f2(20);    // OK
```

```cpp
// СИТУАЦИЯ 2: Шаблон класса
template<typename T>
class Container {
public:
    // ❌ Это НЕ универсальная ссылка!
    // Тип T уже известен при инстанцировании
    void push_back(T&& value);
    
    // ✅ Это универсальная ссылка - новый параметр U
    template<typename U>
    void emplace_back(U&& value);
};

Container<int> c;
int y = 42;
// c.push_back(y);  // ❌ Ошибка: T&& = int&& (rvalue-ссылка)
c.push_back(42);     // OK

c.emplace_back(y);   // OK: U&& - универсальная ссылка
c.emplace_back(42);  // OK
```

## Практические примеры

### 1. **Идеальная передача в конструкторах**

```cpp
class Person {
    std::string name;
public:
    // Универсальная ссылка для идеальной передачи
    template<typename T,
             typename = std::enable_if_t<
                 std::is_convertible_v<T, std::string>
             >>
    explicit Person(T&& n)
        : name(std::forward<T>(n)) {
        std::cout << "T&& constructor\n";
    }
    
    // Конструктор копирования
    Person(const Person& other) : name(other.name) {
        std::cout << "Copy constructor\n";
    }
};

Person p1("Alice");  // T&& constructor
Person p2 = p1;      // Copy constructor
std::string s = "Bob";
Person p3(s);        // T&& constructor
Person p4(std::move(p3));  // Copy constructor
```

### 2. **Variadic templates + универсальные ссылки**

```cpp
#include <tuple>

template<typename... Args>
auto make_all(Args&&... args) {
    // Передаём все аргументы с сохранением категории
    return std::tuple<Args...>(std::forward<Args>(args)...);
}

auto t = make_all(1, 2.5, std::string("hello"));
```

### 3. **Проблемы и решения**

```cpp
// ❌ ПРОБЛЕМА: Избыточные перегрузки
template<typename T>
void bad_overload(T&& value) {
    // Обрабатывает всё...
}

// ✅ РЕШЕНИЕ: Ограничение с помощью SFINAE
template<typename T,
         typename = std::enable_if_t<
             !std::is_same_v<std::remove_reference_t<T>, MyClass>
         >>
void safe_overload(T&& value) {
    // Обрабатывает всё, кроме MyClass
}
```

## Продвинутые техники

### 1. **Универсальные ссылки в лямбдах (C++14+)**

```cpp
auto lambda = [](auto&& param) {
    // param - универсальная ссылка
    return std::forward<decltype(param)>(param);
};

int x = 10;
lambda(x);   // param = int&
lambda(20);  // param = int&&
```

### 2. **Perfect forwarding в фабричных функциях**

```cpp
template<typename T, typename... Args>
std::unique_ptr<T> make_unique(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}

class MyClass {
public:
    MyClass(int a, double b, const std::string& c) {}
};

auto obj = make_unique<MyClass>(1, 3.14, "hello");
```

### 3. **Универсальные ссылки и const**

```cpp
template<typename T>
void with_const(const T&& param);  // ❌ Это НЕ универсальная ссылка!
                                   // const + && = rvalue-ссылка на const

template<typename T>
void without_const(T&& param);     // ✅ Универсальная ссылка
```

## Предупреждения и лучшие практики

### 1. **Избегайте перегрузок с универсальными ссылками**

```cpp
// ❌ ПЛОХО: Может привести к неожиданным вызовам
template<typename T>
void process(T&& value) { /* версия 1 */ }

void process(int value) { /* версия 2 */ }

process(42);  // ❌ Неоднозначность!

// ✅ ЛУЧШЕ: Используйте разные имена или теги
template<typename T>
void process_forwarding(T&& value) { /* ... */ }

void process_value(int value) { /* ... */ }
```

### 2. **Ссылки на ссылки в возвращаемых типах**

```cpp
// ❌ Опасно: может возвращать ссылку на временный объект
template<typename T>
decltype(auto) dangerous(T&& value) {
    return value;  // Может вернуть ссылку на локальную переменную
}

// ✅ Безопасно: используйте std::forward
template<typename T>
decltype(auto) safe(T&& value) {
    return std::forward<T>(value);
}
```

### 3. **Конструкторы с универсальными ссылками**

```cpp
class Complex {
    std::string name;
    int id;
public:
    // ⚠️ Опасный конструктор с двумя универсальными ссылками
    template<typename T1, typename T2>
    Complex(T1&& n, T2&& i)
        : name(std::forward<T1>(n)),
          id(std::forward<T2>(i)) {}
    
    // ❌ Проблема: может скрыть конструктор копирования
};

Complex c1("test", 1);
Complex c2 = c1;  // Ошибка! Нет конструктора копирования
```

## Итог

**Шаблонные конструкторы:**
- Могут подавлять автоматическую генерацию специальных функций
- Требуют осторожности и явного управления
- Часто нуждаются в ограничениях через SFINAE или концепты

**Универсальные ссылки:**
- Это `T&&` или `auto&&` с выводом типа
- Позволяют идеальную передачу (perfect forwarding)
- Требуют `std::forward` для сохранения категории значения
- Могут создавать неоднозначности при перегрузке

Ключевое правило: **универсальные ссылки работают только при выводе типа**. Если тип известен — это обычная rvalue-ссылка.
